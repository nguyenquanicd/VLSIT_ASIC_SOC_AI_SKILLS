# License, copyright and patent evidence

This guide supports technical research, not legal advice or a freedom-to-operate opinion.

## Keep rights categories separate

For every source and major feature, distinguish:

1. **Document copyright and access:** who publishes the datasheet, paper or standard, the stated access terms, and whether local retention is allowed.
2. **Implementation or hardware-description-language license:** rights to use, modify, synthesize, distribute or commercially integrate a reference design or source code. A datasheet is not an implementation license.
3. **Standards access and intellectual-property policy:** specification copyright/access terms, disclosure policy and any licensing commitments. A standard's publication does not automatically grant rights to implement patented claims.
4. **Patent evidence:** identified applications/grants, owners, jurisdictions, published claims, legal status shown by the consulted database, and relevance to the specific feature.
5. **Third-party dependencies:** codecs, firmware, software, interface controllers, analog components or licensed technologies required by an implementation.

Never assume that a feature is free to implement because its description is public, because an open-source implementation exists, or because a limited search found no patent.

## Patent search record

Search terms should include source terminology, functional synonyms, assignee/owner names, inventor names when relevant, and related standard or product terms. Record databases searched, exact queries, filters, dates, publication/grant numbers, jurisdictions and the database's displayed status. Read the claims and prosecution/status context when available; a title or abstract alone is not enough to assert claim relevance.

Mark a result as **identified evidence**, **possible relevance**, **not located in searched sources**, or **unresolved**. State that database status can lag official registers and that legal scope requires qualified counsel. Do not state that no patent exists or that the implementation is cleared.

## Download and retention

Before download, present the candidate URLs, source identity, access basis and copyright/license notice for batch approval. Download only a direct, accessible file or copy a user-provided file that the user is authorized to use. Never use credentials, session cookies, paywall workarounds, scraping that violates a site's restrictions or methods that conceal the download. Record original URL, acquisition date, local filename, checksum, license/access basis and any reuse restriction. Do not place restricted full text inside a public repository, public report or redistributed bundle.

If terms are absent or unclear, record them as unknown and ask the user before retaining or redistributing the material. A right to read is not necessarily a right to redistribute.
